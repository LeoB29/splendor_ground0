# Separate A64/B64 execution contract

23 October 2026. The owner approved implementation and execution after the
[prepared design](move_evaluation_64_study_20261023.md). That scientific design,
its fixed schedules, investment criteria and resource limits remain unchanged.
The implementation is `tools/move_evaluation_64_20261023`; new evidence is confined
to `outputs/move_evaluation_64_20261023_01`. No old source or result is replaced.

## Admission and identity

The model-free preparation authenticates the pinned preparation receipt and
closeout, inherited inputs, new code/tests/review, corrected rules, all checkpoint
and native-binary identities, Python/NumPy and the preserved Torch runtime.
It reconstructs the 18 historical roots with independent transition checks,
creates the 15 corrected-rules fixtures and a parent-only runtime lock, and saves
an immutable `freeze.json`. The runtime lock contains no preselected A64 action.
Actual current A64/B64 actions are sealed after successful fresh computation.

Each new worker records `verify_runtime_sources()` once before loading models.
A has no Entity opponent. B selection uses accepted per-decision reuse with
original Torch module inference; B replay uses the original reference adapter.
Full128 candidate generation remains unchanged. Both arms then derive exactly
the first64 worlds and use separate64 reduction implementations: serial floating
W/D/L reduction in selection and integer half-point/outcome checks in validation.
Neither frozen128 reducer nor its global configuration is changed.

## Ordered execution

The owning windowless watchdog records monotonic and wall origins before source
admission or process creation. One immutable launch claim prevents automatic
restart. The runner uses the same origins. Pilot, qualification, collection and
absolute limits are1/3/6/8 hours, respectively; final verification retains the
last2 hours. Startup, RAM admission, model initialization and all checks count.

Both arm-specific actual-model qualifications precede pilot selection. Each
qualification checks15 rule/interface fixtures,18 fit/face encoded-model checks,
all three actual proposal routes, malformed64 schedules and192 one-turn
continuations through the production64 evaluation body. These small admission
continuations are separate from the54 timed panel requests and their13,696
selection continuations. The pilot then follows the exact prepared request
order: both passes across roots0/6/12, followed by six independent full replays.
Only a passed pilot admits the remaining roots and privacy repeats.

Each selector has a real120-second complete-response limit and must finish in
at most96 seconds to pass the engineering margin. The timing is the trusted
receipt's `receipt_elapsed_seconds`; it includes request delivery, proposal
reproduction, all continuations, compressed trace writing and full response
delivery. Setup is separately capped at60 seconds. Audit requests are capped
at300 seconds. Every limit is clamped to both phase clocks and the global clock;
post-initialization and post-response guards reject clock jumps between samples.

Completed selector evidence is saved before applying the96-second gate. A
margin failure stops the study and preserves the response. Such a result is
neither a benchmark loss nor a correctness-qualified decision: full replay may
not yet have run. Hard deadlines, invalid responses, incomplete workloads,
prefix mismatches or resource failures likewise stop dependent work. There are
no retries, substituted roots, reduced quotas or extensions.

Every core decision has complete independent replay. A also matches archived
first64 outcomes/state/action hashes on all18 roots. B matches those fields and
every decompressed first64 continuation step on the three available roots.
Timing/privacy duplicates must match core scientific outputs and gzip hashes;
only their artifact paths differ. Cached128 results never supply fresh timing.

After54 successful timed requests,36 core replays and all prefix/privacy checks,
seal all choices and the evaluated parent lock. Qualify both raw035/PUCT16
assessment routes on all15 fixtures under actual one-second move clocks. Bind
these files in `qualification_complete.json` before assessment admission.

## Assessment, verification and closure

The prepared breadth gate still requires six changed roots covering all fits.
If it fails, close as insufficient intervention breadth without starting an
assessment. Otherwise use exactly32 fresh paired worlds per root, prescribed
parent-only seeds, natural terminal scores and the unchanged assessment policies.
The first-wave cost gate reads elapsed time and bytes, never scores; all remaining
work plus35% contingency must fit the collection cutoff and evidence cap.

The parent remains free of Torch imports. Its sampler loads the exact frozen
hidden-information source directly to avoid unrelated package initialization;
independent dictionary reconstruction checks every sampled initial world.
Assessment branch evidence includes every actual move and its trusted receipt.
Both branch computation and durable evidence completion must fit120 seconds.
Independent verification checks every branch, actual transition, observer,
response identity, terminal score and qualified PUCT quota. It does not claim
replay of every internal PUCT edge. The primary and independent analyzers must
agree exactly, including the fixed50,000-replicate bootstrap integer stream.

One owned worker tree runs on logical CPU0 after topology checks, with one
numerical thread,2GiB RSS and2GiB new-evidence caps. RAM and disk requirements are
unchanged. No memory wait pauses an active move or branch. Windows job ownership
closes descendants on every exit; failures and partial records are retained.
Success is reported only after source reauthentication, evidence inventory,
analysis and outer process closure. A partial or failed run remains explicitly
unqualified; the larger-data study, training and whole-game strength runs remain
deferred.
