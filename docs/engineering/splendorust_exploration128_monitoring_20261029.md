# Exploration128 monitoring and bounded technical recovery

The user requested proactive handling of stopped work on 29 October 2026.
This policy accompanies the separately frozen wider-budget attempt02. It changes
neither player execution nor any scientific or verification requirement.

## Monitoring

A heartbeat in the existing chat checks approximately every fifteen minutes.
It reads AGENT_CURRENT.md, small status and failure receipts, recent progress,
and exact owner identities. It does not run an extra host sampler or inspect
interim scores to make scientific decisions. Routine healthy checks stay quiet.
Report a failure, unexpected owner exit, confirmed lack of progress, completed
verification or a blocker requiring user action. An old receipt or an unchanged
failure is not a new alert. Store any alert deduplication state outside the
active attempt, in outputs/splendorust_exploration128_monitor_20261029.

The heartbeat depends on the local computer and app being available. It is not
an always-on service and does not guarantee detection within fifteen minutes.

## Automatic technical follow-through

On an unexpected stop, preserve all evidence and first establish whether the
process is still alive. Diagnose from saved evidence, reproduce a checker or
supervision defect where possible, and prepare and test a separate correction
without waiting for another status request. Report the stop and intended remedy.

At most one automatic technical recovery may be prepared and launched for this
study, with at most three hours spent on diagnosis, repair and qualification;
all such work counts within attempt02's original 48-hour deadline and resource
envelope. It requires independent review and a separately recorded recovery
freeze. The original failed attempt stays incomplete and the recovery is
reported separately. Recovery must retain the original clock origin, remaining
budgets, exact players, rules, schedule, all outcomes, and acceptance criteria.
It may continue only if existing evidence unambiguously establishes a safe
boundary. It must not reset an active move clock, retry a failed decision,
replace or discard a game, relabel a failure, overwrite frozen files, extend
resources, or weaken verification. If these conditions cannot be met, finish a
concrete proposed remedy and promptly request the necessary decision.

Scientific changes, additional studies, more games, threshold changes and budget
extensions are outside this policy. Ordinary valid stage transitions already
belong to the frozen controller. A valid negative finding is a result, not a
technical failure to repair. Keep external testing, training and larger-data
work deferred.

## Completion

Do not equate a completion file with acceptance. Check the independent reader,
required acceptance receipts, actual owner exit and owned-process cleanup.
Update continuity and report the findings with their limitations, then pause
the heartbeat. Report recovered verification distinctly from original success.
