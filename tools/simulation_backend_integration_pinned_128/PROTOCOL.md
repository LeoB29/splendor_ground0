# Full historical collector integration on one fixed logical processor

The owner authorized this controlled repeat after the earlier real-collector
integration passed correctness but failed its net-time gate, and short controlled
diagnostics established that worker placement can reverse the measured comparison.
The previous timing failure remains part of the evidence. This test makes no
changes to the running structured_proposer_128 study, any frozen source, any
existing receipt, or any default backend. No current scientific outcomes are read.

## Fixed workload and order

Reuse exactly the prior isolated integration's historical panel: roots 517, 251,
382 from completed large_corpus_optimization_128, with the same snapshots and
test fixture indices 0, 1, 2. Keep all nine authenticated models, original035
continuation weights, the original collector, all 128 selection worlds, and all
128 independent assessment worlds for the locked distinct choices. No additional
root or seed selection is allowed after seeing timings. Authenticate the prior
plan binding and every historical listed code/artifact hash; newly added tool
files do not invalidate the historical inventory or authorize changed bytes.

Run 12 clean collection jobs before fault injection or independent auditing:

1. Repeat 0: roots 0, 1, 2, reference then fast035 for each root.
2. Repeat 1: roots 2, 1, 0, fast035 then reference for each root.

Every job uses a fresh hidden worker with one numerical thread and below-normal
priority. Pin only that worker to logical CPU 0, group 0, before model loading.
Freeze the full Windows CPU-set mapping and exact target metadata. Require CPU 0
to be in this host's highest efficiency class. Validate process affinity and
sample the actual computation thread's CPU at the existing one-second guard
cadence. Restore the worker's previous affinity in finally, including on an
unexpected exception, and save an immutable restoration receipt. A hard OS kill
cannot run finally, but destroys the only process whose affinity was changed.
The controller and main experiment affinity remain unchanged. This controls
placement on one logical processor; sibling contention, host activity, clocks,
thermal behavior and operating-system scheduling remain possible influences.

## Integration, recovery and independent verification

Reuse the frozen real-collector worker and its continuation-only optional
backend. Temporary process-local adapters change dispatch, CPU telemetry and
the final result's publication timing only. Root proposal scoring, repetition
proofs, selection arithmetic and independent replay retain the original policy.
The temporary adapters restore their globals on exit. No encoded-input audit or
profiling callback is introduced into the timed collections.

After all 12 clean timings, intentionally interrupt the middle fast root
immediately after its durable selection seal and before assessment. Preserve its
failed root, full selection and seal; require the original collector to refuse
overwriting it. Then collect that whole root again in a new process and attempt
directory. Both these jobs are outside the timing pool. Do not reuse partial
selection. Compare recovered science and statistics with all four clean middle
root results.

Run the original full independent audit on each of the three repeat-0 fast
roots, followed by the original summary. The three-root original sample plan
makes every root a stress root, so every selection and assessment continuation
is replayed. Each audit retry replays completely into a new directory. Only the
exact final audit receipt destination and its returned artifact path are routed
to the new attempt; all replay inputs, calculations and substance stay original.
Total schedule: 12 clean collections, interruption, whole-root recovery, three
full audits and summary = 18 successful jobs.

Require all four complete scientific records and original statistics rows for
each root to be identical. Normalize only the earlier integration's explicitly
enumerated operational timestamps/timings and artifact location fields, after
authenticating raw selection and seal hashes. Include exact proposals, candidate
order, seeds, trajectories/final states/outcomes, choices, proofs and both blocks.
Validate backend block identities/counts, all model identities, placement,
restoration and immutable completion receipts. The independent auditor uses the
unaltered reference implementation even for roots generated with fast035.

## Timing gate and interpretation

Use parent-measured net elapsed time for only the 12 clean collection jobs. It
includes fresh process startup, imports/authentication, model initialization,
proposal formation, selection, assessment, output writes, affinity restoration
and process exit. The parent retains the original two-second polling cadence;
the per-job quantization is disclosed by the existing controller implementation.
Report each root pair and both three-root repeats, their collection/CPU times,
and the pooled net totals. Acceptance requires every correctness/recovery/audit
gate plus pooled fast net time strictly below pooled reference net time. Do not
discard a slow repeat or a memory-pressure interval. Fault/recovery/audit/summary
costs count toward the task budget but never the clean comparison denominator.
This fixed panel is descriptive under the observed host load, not a new random
sample of positions, a universal speed estimate or a playing-strength result.
Even acceptance does not adopt the backend in any current or future experiment
without an explicit per-experiment choice.

## Resources and durable evidence

Retain the original resource guards: one child at a time, two hours cumulative
job wall time including failures and planned interruption, 6 GiB system commit
reserve, 5 GiB disk reserve, 2 GiB worker RSS/peak/private cap, 256 MiB parent cap.
Before each worker require commit reserve plus its full worker and parent
allocations. Available physical RAM remains telemetry only, with no pause/stop
threshold. Preserve parent leases, abort checks, original-main phase checks and
hidden child creation. Stop this isolated work if the main study enters source
generation/evaluation. Only main operational progress and its completion flag
may be read. Original main code, freeze and launch seal remain hash-bound.

Use a new output directory only. Completed receipts must form an exact schedule
prefix: unknown entries or gaps fail closed rather than change temporal order.
Resume reuses only authenticated complete jobs; uncompleted jobs restart wholly
in a new attempt. Preserve every failed attempt. A prior orphaned start without
an end receipt is conservatively charged wall time since its epoch. A run lock,
own-worker liveness checks and process lease prevent overlapping resumes. No
automatic retry, recurring monitor or detached monitoring loop is installed.
All prior evidence and dirty-worktree changes are preserved.
